# Проверка на Windows (ноутбук Elyor, Windows 10)

На сервере разработки Windows нет: ядро и логика экранов проверены тестами на Linux, а **окно, трей, автозапуск
и установщик ни разу не запускались**. Это первая проверка на живой Windows.

## Как получить сборку на ноутбук

1. **Собрать на ноутбуке** (нужны git и .NET SDK 10, права администратора не нужны):
   `git clone https://github.com/pico-soft/X-Gates-Win` → `git checkout wip/windows-shell` →
   `powershell -ExecutionPolicy Bypass -File tools\windows\check.ps1`.
2. **GitHub Actions** (`tools/ci/windows.yml`; включается копированием в `.github/workflows/`; ручной запуск): собирает, гоняет тесты на Windows,
   запускает окно и снимает скриншоты, собирает и ставит/удаляет MSI. Чтобы КК мог отправить этот файл, токену `gh`
   на сервере нужно право `workflow`: `! gh auth refresh -h github.com -s workflow` (решение Elyor: тратит минуты
   Actions приватного репозитория — один прогон ≈ 10–15 мин, у Windows-раннера множитель ×2).

## Что проверить (по порядку)

| # | Что | Ожидается |
|---|-----|-----------|
| 1 | Установка MSI **обычным пользователем** | без запроса UAC; программа в `%LOCALAPPDATA%\Programs\X-Gates Win`, ярлык в «Пуск» |
| 2 | Первый запуск | окно с тремя вкладками; значок в трее; данные в `%LOCALAPPDATA%\X-Gates` |
| 3 | Подписки → вставить ссылки / URL | серверы появились, статус «вставка: +N …» |
| 4 | Главная → «Самый быстрый» | прогресс по этапам, подключение, плашка зелёная, IP показан |
| 5 | Браузер: прокси `127.0.0.1:10816` (HTTP) или `10815` (SOCKS5) | сайты открываются через туннель; системный прокси Windows НЕ изменён |
| 6 | Занять порт (`python -m http.server 10816`) → подключиться | понятный текст «Порт 10816 занят другой программой…» |
| 7 | Настройки → сменить порты → «Применить» | прокси переподнят на новых портах |
| 8 | Закрыть окно (крестик) | окно скрылось, значок в трее остался, прокси работает |
| 9 | Запустить ярлык ещё раз | открывается то же окно, второй значок не появляется |
| 10 | «Запускать при входе в Windows» → выйти/войти | приложение в трее, поднят последний сервер, окно не открыто |
| 11 | Сон/выход из сна, смена Wi-Fi | связь восстанавливается сама (монитор) |
| 12 | Трей → «Выход» | ядро остановлено (нет `xray.exe` в диспетчере задач), порты свободны |
| 13 | Удаление через «Параметры → Приложения» | файлы программы удалены; данные в `%LOCALAPPDATA%\X-Gates` остались |

Журнал приложения: `%LOCALAPPDATA%\X-Gates\logs\x-gates.log`; отчёты о сбоях: `%LOCALAPPDATA%\X-Gates\crashes`.

## Если КК должен управлять ноутбуком сам (по желанию)

Вариант «как Phone Bridge»: на ноутбуке OpenSSH Server, слушает только `127.0.0.1`, ноутбук держит обратный
туннель на сервер (`ssh -N -R 2222:127.0.0.1:22 elyor@<сервер>`). Окна из SSH-сеанса не видны на экране —
запуск приложения и скриншоты идут через задачу планировщика в интерактивном сеансе. **Установка OpenSSH Server
требует прав администратора и меняет настройки ноутбука — только по решению Elyor**; КК подготовит скрипт под
выбранный вариант.
