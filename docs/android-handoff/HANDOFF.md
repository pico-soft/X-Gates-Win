# Хэндофф X-Gates-Win → X-Gates (Android): 9 исправлений + монитор на зарядке + лицензия MIT

**От:** КК проекта X-Gates-Win (`~/projects/X-Gates-Win`, Windows-порт этого приложения).
**Кому:** КК проекта X-Gates (Android, `~/projects/XrayProxyDroid`).
**Решение Elyor (2026-10-30):** ошибки, найденные при порте, исправить в Windows-версии, а для Android — отдельный
хэндофф: «чтобы при запуске Claude Code в папке Android-версии он прочитал его и внёс исправления».
**Дополнено 2026-10-31 решениями Elyor:** `0010` — монитор на зарядке, как в Windows-версии (на объяснение
«делать ли на Android» Elyor ответил «принято»); `0011` — лицензия MIT («MIT на все в pico-soft»).
**Дата:** 2026-10-31. **Основа патчей:** `4b0bebb` (main Android на момент подготовки).

## Что сделать

Применить 11 патчей из `handoff-win-fixes/` (по порядку номеров) по **твоим** правилам проекта ([[commit-at-discretion]]): по одному →
сборка → установка на телефон → проверка → отдельный коммит (+ push main). Теги и релизы — только по слову Elyor.

```bash
git status                                    # дерево должно быть чистым; HEAD — 4b0bebb или его потомок
git apply --check handoff-win-fixes/0001-*.patch && git apply handoff-win-fixes/0001-*.patch
# сборка, установка, проверка (см. таблицу), затем коммит; сообщение можно взять из шапки патча (Subject + тело)
```

Используй `git apply`, а не `git am`: `git am` сразу коммитит, а по правилам проекта коммит — после проверки.
Если HEAD ушёл вперёд и патч не ложится — перенеси правку вручную (смысл в описании ниже и в теле патча).

## Что уже проверено (на стороне Windows-КК)

- Все 11 патчей по очереди ложатся на чистый клон `4b0bebb`, итог — байт в байт проверенная копия. На ней
  `./gradlew :app:testDebugUnitTest` — **40/40** (36 прежних + новые `splithttp_normalizes_to_xhttp`,
  `keeps exception and method names but masks keys`, 3 в `ChargerChecksTest`), `:app:assembleDebug` собирается.
- Golden-сверка (X-Gates-Win `tools/golden`): эталон снят с **патченного** Kotlin (0001–0002 меняют парсер и
  конфиг). C#-версия совпала с ним на всём корпусе. Конфиг splithttp→xhttp принят настоящим xray v26.7.28
  («Configuration OK»).
- Каждое исправление в C#-зеркале закрыто тестом, который ДО правки падал, а ПОСЛЕ проходит (кроме №6 и №9 —
  там тест новый и проверяет итог).
- **На телефоне не проверено ничего** — это твоя часть.

## Патчи

| № | Файл | Что ломалось у пользователя | Проверка на телефоне |
|---|------|-----------------------------|----------------------|
| 0001 | `xray/XrayConfigBuilder.kt` (+ тест) | серверы с транспортом `splithttp` (старое имя xhttp) из JSON-подписок и ссылок не собирались: «unsupported transport» | подписка/ссылка с `type=splithttp` → сервер подключается (или хотя бы нет «unsupported transport» в журнале) |
| 0002 | `xray/link/VmessParser.kt` | ~1,5% реальных vmess-ссылок вида `vmess://<base64>=?хвост` (без `&`) молча отбрасывались | вставить такую ссылку → сервер добавлен |
| 0003 | `monitor/NetworkMonitor.kt` | на пуле меньше 10 серверов фоновый рейтинг топа падал «Cannot coerce value to an empty range» и ничего не мерил | маленькая подписка (< 10 серверов), на зарядке → в журнале «Фон: топ обновлён» вместо «Ошибка фон-рейтинга топа» |
| 0004 | `xray/ServerSpeedTester.kt` | один сервер с битым конфигом (напр. битый ключ reality — ядро не стартует) обрывал всю загрузку подписки через temp-инстанс (ступень 6) | на телефоне трудно воспроизвести; проверить, что обновление подписок работает как раньше |
| 0005 | `service/XrayProxyService.kt` | гонка операций с ядром: из двух быстрых стартов («первый рабочий» → «точный топ») мог остаться поднятым не последний сервер (статус — один, туннель — другой); старт, за которым сразу «Стоп», поднимал ядро после стопа | «Самый быстрый» → внешний IP на плашке совпадает с выбранным сервером; ▶ и сразу ■ → остаётся остановлено; автозапуск и «Только Wi-Fi» работают как раньше |
| 0006 | `crash/CrashReporter.kt` (+ тест) | маска отчёта о сбое закрывала имена исключений (`IllegalArgumentException`…) и длинные методы — не было видно, что упало | юнит-тест; при случае — отчёт о сбое содержит имя исключения |
| 0007 | `update/UpdateInstaller.kt` | файл обновления дошёл, но SHA-256 не совпал, а прокси выключен → ложное «Прямой доступ к GitHub заблокирован, а прокси не запущен» | на телефоне трудно воспроизвести; проверить, что обычное обновление не сломано |
| 0008 | `xray/FullTestRunner.kt` | «Не использовать» на рабочем сервере обычно ничего не переключал: полный тест брал отложенный активный «текущим лучшим» | подключиться к рабочему → «Не использовать» → туннель на другом сервере (если есть хоть один рабочий) |
| 0009 | `MainActivity.kt` (`buildDiscriminators`) | одноимённые серверы с одинаковым протоколом были неотличимы: у всех подпись «… · \|\|\|\|» | два одноимённых сервера → подписи различаются адресом:портом (тот же адрес — «#xxxx») |
| 0010 | `monitor/NetworkMonitor.kt`, `MainActivity.kt` (+ тест) | не ошибка, а **новое правило Elyor**: на зарядке упавший сервер заменялся через 2–2,5 мин (проверка 60 с + grace 90 с), хотя батарея не тратится. Теперь на зарядке по Wi-Fi без экономии трафика — проверка раз в 10 с, обрыв после 30 с тишины → ~35 с | на зарядке по Wi-Fi: «● Проверка связи каждые 10 с (на зарядке)»; выключить рабочий сервер (или отрезать его) → переключение примерно за 35–45 с; на батарее и на мобильной — как раньше (60 с); ночь на зарядке — телефон заметно не греется, расход трафика проверок ~1 МБ/ч |
| 0011 | `LICENSE`, `README.md` | лицензии не было; решение Elyor — MIT на все репозитории pico-soft | GitHub показывает «MIT License» на странице репозитория после push |

Подробности «почему» — в теле каждого патча и в X-Gates-Win `docs/decisions.md`, раздел «Найдено в Android-коде».

## Важно для паритета

- Windows-версия уже содержит **ровно эти** правки. Если при переносе меняешь решение (другой текст, другая
  логика) — скажи Elyor: Windows-КК выровняет у себя, иначе версии разойдутся.
- После твоих коммитов Windows-КК синхронизируется по `UPSTREAM-SYNC.md` своего репозитория. Golden-эталон там
  сейчас снят с «4b0bebb + патчи 0001–0002»; после твоего коммита он должен совпасть с эталоном от твоего HEAD.
