# Синхронизация с Android-версией (upstream)

Android X-Gates продолжает развиваться и получать багфиксы в `/home/elyor/projects/XrayProxyDroid`
(remote `upstream`; GitHub — `upstream-github`). Этот файл — **как правки оттуда попадают сюда**.

## Маркер

| Дата | Android-коммит, до которого перенесено | Что | Кто |
|---|---|---|---|
| 2026-10-30 | `4b0bebb` (main после v0.63 + 2 фикса) | точка форка: весь код Android на этот коммит | Android-КК |

Следующая синхронизация начинается с коммитов **после** последнего маркера.

## Процедура (пока схема B/C, см. ниже)

```bash
git fetch upstream
git log --oneline --reverse <маркер>..upstream/main      # что нового в Android
git show --stat <sha>                                     # что затронуто
```

Каждый коммит классифицировать:
- **core** (парсеры, подписки, xray-конфиги, фильтры, замеры, монитор, трафик, проверка обновлений) →
  переносить: `git cherry-pick -x <sha>`, если файл лежит по тому же пути и почти не изменён; иначе — вручную
  тем же смыслом, в теле коммита `upstream: <sha>`.
- **UI** (`MainActivity.kt`) → переносить по смыслу в Compose Desktop-эквивалент.
- **Android-only** (FGS, батарея, Doze, APK-установка, VPN-обход, `release:`/версии) → пропустить, отметить.

После — добавить строку в таблицу маркера (до какого sha, что перенесено/пропущено).

## Варианты долгосрочной схемы (решить с Elyor)

- **A. Монорепо с общим модулем `:core`** (Android `app` + Windows `:desktop` зависят от одного `:core`).
  Фикс делается один раз и сразу попадает в обе платформы. Требует разовой перестройки Android-проекта на
  `:core` (механически, но с проверкой на телефонах). **Лучшее в долгую.**
- **B. Форк + периодический `git merge upstream/main`** с детекцией переименований. Работает, пока общие файлы
  остаются по тем же путям и мало правятся здесь. Конфликты — в UI и платформенных местах.
- **C. Ручной перенос по журналу** (процедура выше, cherry-pick/по смыслу). Просто, но трудоёмко и легко
  пропустить фикс.

**Рекомендация Android-КК:** начать с C/B, но писать `:core` так, будто завтра будет A: те же имена файлов,
пакетов (`com.picosoft.xrayproxydroid.*`), классов и функций; платформенное — за интерфейсами; не
«улучшать» общую логику в одностороннем порядке — улучшения общей логики делать В ОБОИХ проектах.
