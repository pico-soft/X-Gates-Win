# Синхронизация с Android-версией (upstream)

Android X-Gates продолжает развиваться и получать багфиксы в `/home/elyor/projects/XrayProxyDroid`
(remote `upstream`; GitHub — `upstream-github`). Этот файл — **как правки оттуда попадают сюда**.

## Обратный поток: Windows → Android (хэндофф)

| Дата | Что | Где | Статус |
|---|---|---|---|
| 2026-10-31 | 11 исправлений, найденных при порте | `docs/android-handoff/` (HANDOFF.md + patches/0001–0011, основа `4b0bebb`) | принято в Android v0.64 |
| 2026-10-31 — 2026-11-02 | Инструкции `0012`–`0018`: TLS, XHTTP, фрагментация, монитор, mKCP, точные замеры | там же | принято в Android v0.64 |
| 2026-11-04 | Дальнейшие исправления и уточнения Android-КК | коммиты Android до `856f191` | разобраны и отражены здесь |

Хэндофф закрыт подтверждением Android-КК от 2026-11-04. Само сообщение `HANDOFF-FROM-ANDROID.md` остаётся локальным и в Git не добавляется.

**Golden снят с `403c0ed` (v0.64), как указал Android-КК.** `WithoutAllowInsecure` и `WithoutKcp` удалены: конфиги сравниваются
напрямую. `JsonIgnore` в `ServerProfile` НЕ убирать: в Android у новых полей `@EncodeDefault(NEVER)`, пустые поля не пишутся,
поэтому сериализация совпадает. Форматирование массива `finalmask` выровнено с Kotlin. `tlsFragment`: на Android в `settings.json`,
здесь в `win_settings.json`, расхождение принято; `StoreCompatTests` исключает только это поле из общего JSON и проверяет его эталонное
значение `false`, остальные поля сравниваются напрямую.

**Намеренные расхождения с Android:** расписание `upgradeCheckMs`; `monitorOptimizeSkipAboveMbps` здесь не читается; фоновая работа
монитора вынесена из цикла проверки, поэтому Android-прерывание фонового рейтинга по пингу активного здесь не требуется. В послевосстановительном
рейтинге общий цикл сохранён, поэтому прерывание `ce41833` перенесено. Обе версии перебирают следующий живой сервер и ограничивают цепочку 32 отказами.

**Другие намеренные расхождения Windows:** `FirstAliveRace` (и в лестнице восстановления), пинг в 48 потоков с пределом трёх UDP-ядер,
граница «Живых» `LiveListPrefs`, проверка обновления при каждом запуске без ожидания туннеля, потолок активной пробы монитора,
`ThreadPoolSetup`, переключатель тёмной темы. Причины — `docs/decisions.md`.

**Не перенесено как Android-only:** `MY_PACKAGE_REPLACED` и Android-релизы. Ранняя загрузка хранилищ из `131fe9b` уже обеспечена
`AppBootstrap.start` до запуска сервиса. Определение лимитной сети Windows пока не реализовано; это явно указано в подсказке настройки,
а не выдаётся за работающий перенос `1349185`.

## Процедура (пока схема B/C, см. ниже)

```bash
git fetch upstream
git log --oneline --reverse <маркер>..upstream/main      # что нового в Android
git show --stat <sha>                                     # что затронуто
```

Каждый коммит классифицировать:
- **core** (парсеры, подписки, xray-конфиги, фильтры, замеры, монитор, трафик, проверка обновлений) →
  переносить: `git cherry-pick -x <sha>`, если файл лежит по тому же пути и почти не изменён; иначе — вручную
  тем же смыслом, в теле коммита `upstream: <sha>`.
- **UI** (`MainActivity.kt`) → переносить по смыслу в Compose Desktop-эквивалент.
- **Android-only** (FGS, батарея, Doze, APK-установка, VPN-обход, `release:`/версии) → пропустить, отметить.

После — добавить строку в таблицу маркера (до какого sha, что перенесено/пропущено).

## Варианты долгосрочной схемы (решить с Elyor)

- **A. Монорепо с общим модулем `:core`** (Android `app` + Windows `:desktop` зависят от одного `:core`).
  Фикс делается один раз и сразу попадает в обе платформы. Требует разовой перестройки Android-проекта на
  `:core` (механически, но с проверкой на телефонах). **Лучшее в долгую.**
- **B. Форк + периодический `git merge upstream/main`** с детекцией переименований. Работает, пока общие файлы
  остаются по тем же путям и мало правятся здесь. Конфликты — в UI и платформенных местах.
- **C. Ручной перенос по журналу** (процедура выше, cherry-pick/по смыслу). Просто, но трудоёмко и легко
  пропустить фикс.

**Рекомендация Android-КК:** начать с C/B, но писать `:core` так, будто завтра будет A: те же имена файлов,
пакетов (`com.picosoft.xrayproxydroid.*`), классов и функций; платформенное — за интерфейсами; не
«улучшать» общую логику в одностороннем порядке — улучшения общей логики делать В ОБОИХ проектах.
