## 1. Цель и рамки

**Что делаем.** Windows-версию приложения **X-Gates** (Android: `com.picosoft.xrayproxydroid`, текущая
версия 0.63 + неопубликованные фиксы до коммита `4b0bebb`). Функционально — **то же самое**, интерфейс —
**похожий** (те же вкладки/блоки/тексты, по-русски).

**Что это за приложение (кратко).** Обход блокировок в РФ: поднимает **локальный прокси** на движке
**xray-core** и гоняет трафик через зарубежные серверы из подписок пользователя (`vless` / `vmess` /
`trojan` / `shadowsocks`, а также JSON-конфиги Xray). **Не VPN**: не перехватывает весь трафик системы —
нужные приложения (браузер, Telegram) настраиваются на прокси вручную. Уживается с системным VPN.

**Жёсткие требования Elyor для Windows:**
- Поднимаем **ОТДЕЛЬНЫЙ локальный прокси**: SOCKS5 `127.0.0.1:10815` и HTTP `127.0.0.1:10816` (те же
  порты, что на Android — так проще инструкции и привычки).
- **Системный прокси НЕ трогаем.** Никаких изменений WinINET/WinHTTP-прокси, реестра
  `Internet Settings`, PAC, `netsh winhttp`. Никаких TUN/драйверов/WFP, никакого «режима VPN».
  Приложения пользователь направляет на наш порт сам (инструкции — в UI, как на Android
  «Настройте браузер и Telegram»).
- Всё остальное — функционально как на Android (§3), интерфейс похожий.
- ОС: **Windows 10 x64** (Windows 11 — должно работать само).

**Чего НЕ делаем (без отдельного решения Elyor):** Linux/macOS-сборки, свои серверы, сбор телеметрии,
системный прокси/TUN, публикацию релизов без явного слова Elyor.

## 5. Рекомендуемая архитектура Windows-версии

> **2026-10-29: Elyor выбрал C# / .NET 10 + WPF** (нативнее) — рекомендация ниже про Kotlin/Compose
> отвергнута; модульная схема (`:core` за интерфейсами + UI) и всё про xray.exe/данные/трей/обновления — в силе.
> См. `docs/decisions.md`.

**Рекомендация: Kotlin/JVM 21 + Compose Multiplatform (Desktop), xray-core как `xray.exe`.**

Почему так (а не .NET/WPF, Go+Wails, Tauri/Electron):
- ~70% логики — чистый Kotlin/JVM (§4): берём как есть, а не переписываем 10+ тыс. строк с риском
  потерять выстраданные нюансы (каждый «Пр.N» — полевой баг).
- UI на Android — Jetpack Compose → Compose Desktop: те же composables, «похожий интерфейс» почти даром.
- **Багфиксы из Android переносятся механически** (те же файлы/классы/имена) — см. `UPSTREAM-SYNC.md`.
- Минусы (приняты): дистрибутив ~90–120 МБ (вшитый JRE), RAM ~150–250 МБ. Elyor может переиграть (§13).

**Модули (предложение):**
- `:core` — чистый Kotlin/JVM: парсеры, конфиги xray, подписки, фильтры, тесты/замеры, монитор, трафик,
  настройки, проверка обновлений. Платформенные зависимости — за интерфейсами (`Platform`: логгер,
  каталог данных, состояние сети, запуск ядра, уведомления, часы/сон).
- `:desktop` — Compose Desktop UI + Windows-реализация `Platform` + трей + упаковка.
- Android-модуль `app/` в форке — **справочник**, не собирается в Windows-сборку. (Удалять ли его из форка —
  решить вместе с вопросом синхронизации, `UPSTREAM-SYNC.md`.)

**Ядро xray на Windows:**
- Официальный релиз `XTLS/Xray-core` → `Xray-windows-64.zip` (`xray.exe` + `geoip.dat` + `geosite.dat`).
  Версию держать близкой к Android (там Xray-core **v26.7.28**, Lib v39). Проверять sha256 при упаковке.
- Боевой инстанс: дочерний процесс `xray.exe run -c <config.json>` (конфиг — тем же `XrayConfigBuilder`:
  inbounds socks 10815 + http 10816 на 127.0.0.1, outbound proxy + freedom direct). Без окна консоли.
  Корректно гасить при выходе/падении (Job Object или явный kill), не оставлять сирот на портах.
- Статистика трафика (на Android `queryStats("proxy","uplink/downlink")` со сбросом): добавить в конфиг
  `api` + `stats` + api-inbound на 127.0.0.1:<свободный порт> и читать `StatsService`
  (`xray api statsquery --reset` или gRPC). Сумма дельт должна быть верной (на Android — read-and-reset).
- Temp-инстансы для замеров/real-ping (на Android — `Libv2ray.newCoreController` на эфемерном порту,
  `XrayConfigBuilder.buildForSpeedTest`): отдельный процесс `xray.exe` на эфемерном socks-порту, замер через
  него, kill. Учесть стоимость запуска процесса (~50–150 мс) и пул параллельности (`pingPool`/`speedPool`).

**Данные:** `%APPDATA%\X-Gates\` — те же JSON-файлы/схемы, что в `filesDir` Android (sources.json,
настройки, стоп-лист, трафик, журнал монитора, last server, update_check.json). Миграции схем — как на
Android (поля с дефолтами, `ignoreUnknownKeys`).

**Жизненный цикл:** одно окно + **значок в трее** (аналог foreground-уведомления: статус, «Показать»,
«Самый быстрый», «Стоп», «Выход»). Закрытие окна = свернуть в трей (настраиваемо). Один экземпляр
(single-instance lock; второй запуск — показать окно первого). Монитор — корутина в процессе.

**Автозапуск при входе в Windows:** опция (по умолчанию ВЫКЛ, как «запуск после перезагрузки» на Android)
— `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` или ярлык в `shell:startup`. Это НЕ системный прокси
и разрешено; без админ-прав.

**Обновления:** отдельный репозиторий релизов (предложение `pico-soft/X-Gates-Win`, решает Elyor) — тот же
механизм: `releases/latest` (API + запасной путь по тегу!), `update.json` (versionCode/versionName/notes/
packageName/artifacts[fileName, sha256]), каскад загрузки, sha256. Вместо проверки APK-подписи —
**подпись update.json/инсталлятора своим ключом** (ed25519/minisign, публичный ключ вшит) — т.к.
Authenticode-сертификата нет. Установка: скачанный установщик → запуск → выход приложения.

**Упаковка:** `jpackage` (через плагин Compose Desktop `nativeDistributions`) → MSI/EXE с вшитым JRE.
Собирается **только на Windows** → GitHub Actions `windows-latest` (или Windows-машина Elyor). Разработка и
unit-тесты — на этом Linux-сервере.

## 7. Что специфично Android и как с этим быть

- **VPN-логика** (`SystemVpnState`, `NetworkUtils`, ступени 3–4 каскада, `bypassSystemVpn`): на Android
  приложение умеет ходить МИМО чужого VPN. На Windows по умолчанию — маршрутом ОС (через VPN, если он
  включён); ступени 3–4 каскада — «пропущено (не применимо)». Обход — фаза 2.
- **Doze/батарея/«Работа в фоне»** — не переносить; вместо этого «Сворачивать в трей», «Запускать при входе».
- **Мобильная сеть** (экономия по сети, «Только Wi-Fi») — Windows: metered-подключение; фаза 2.
- **Белые списки РФ** (`WhiteListDetector`: google↓/yandex↑ → только серверы белых источников) — **переносим**
  целиком, это логика сети, не платформы.

## 8. Уроки Android-версии, которые НЕЛЬЗЯ потерять (грабли с полей)

1. **Пинг ≠ живой.** Пинг — TCP-коннект host:port (ТЗ Elyor). На сетях РФ (особенно мобильных) сотни
   серверов принимают TCP, но трафик не несут. Живость = реальная передача через туннель (внешний IP,
   скачанные байты). Не путать в UI: «Живые» = свежий успешный замер.
2. **Пробники замера** — только глобально достижимые (Cloudflare `__down?bytes=N` → OVH → thinkbroadband),
   выбирать тот, что фетчится НАПРЯМУЮ; **tele2 через туннель мёртв** (RU-only) — не использовать нигде
   (`tunnelProbes()`, коммиты f8ba302, 11776cc).
3. **Активный сервер в «Живых» — только при подтверждённой связи** (коммит 4b0bebb); внешний IP/«зелёный» —
   только факт для ЭТОГО serverKey (Пр.123).
4. **Подписки**: UA `v2rayNG/1.8.0` (иначе панели отдают Clash YAML); base64/plain/**JSON-массив конфигов
   Xray** (Furk, `JsonConfigParser`); реестр серверов один по `serverKey`, измерения сохраняются при
   переимпорте; `rawBodies` — пересборка реестра при удалении/выключении источника (Пр.85); зеркала
   github raw / jsdelivr / githack; каскад загрузки (напрямую → через свой прокси → … → temp-инстанс).
5. **Обновления**: APK-адрес — **по тегу релиза**, не `latest/download/<файл>` (404 после выхода новее);
   перепроверка перед скачиванием, если проверке >10 мин; сообщение об ошибке — под кнопкой (коммит
   235d3d2). Контракт `update.json` — в его `_comment` (`release/update.json`). Кавычки в notes — только « ».
6. **Порты**: МегаФон режет нестандартные порты (443 ок). Серверы на нестандартных портах — чаще мёртвые.
7. **Потоки/таймеры**: опрос трафика — один поток на поколение (утечка «+1 поток на переключение», коммит
   2664493); замеры — бюджет времени + сторож застоя (Пр.103); single-flight для внешнего IP.
8. **Полный тест** (Пр.151/ТЗ 2026-10-14): пинг всех → минимальный замер (≈100 КБ) до 10 годных (скан
   до 180) → полный замер топа → переключение на быстрейший (инкумбент — кратный порог). Не «мерить всех».
9. **Данные пользователя священны** — миграции без потерь; никаких «очистить всё» без явного подтверждения.
10. **Секреты** не выводить никогда (ключи подписи, токены, PIN) — см. `CLAUDE.md`.

Подробности каждого — `grep` по архиву памяти Mac (§2.3) и `git log -S`/`git log --grep` в этом форке.

## 9. Этапы (предложение; уточнить в плане)

1. **Каркас**: Gradle (JDK 21), модули `:core`/`:desktop`, Compose Desktop «Hello», CI на GitHub Actions
   (windows-latest: сборка + `packageMsi`). Перенос `:core` + unit-тестов, зелёные на Linux.
2. **Ядро**: `XrayProcess` (старт/стоп/статистика/temp-инстансы) — интеграционные тесты на Linux с
   linux-бинарём xray (та же версия), затем на Windows.
3. **MVP**: подписки (добавить/обновить), список серверов, подключение ▶, плашка статуса, «Стоп»,
   SOCKS/HTTP слушают, браузер ходит через прокси, системный прокси не тронут.
4. **Паритет логики**: пинг, «Самый быстрый», замеры, «Живые/Ранее измеренные», стоп-лист, автомониторинг
   и восстановление, трафик, белые списки, журнал.
5. **Windows-обвязка**: трей, single-instance, автозапуск при входе, логи, отчёты о сбоях.
6. **Обновления + упаковка + подпись** → первый релиз (только по слову Elyor).
7. Фаза 2: обход системного VPN, metered/экономия по сети, тосты.

**Критерий готовности MVP**: на чистой Windows 10 установка → добавить подписку → «Самый быстрый» →
Firefox/Telegram на `127.0.0.1:10815` открывают заблокированное; `netsh winhttp show proxy` и
`Internet Settings` — без изменений; выход из приложения не оставляет `xray.exe`.

## 10. Где разрабатывать и как проверять

- **Этот сервер (Ubuntu, без sudo)**: JDK 21 — `~/.local/opt/jdk-21` (`JAVA_HOME`), Gradle wrapper,
  `gh` (авторизован как `pico-soft`). **dl.google.com по IPv6 отдаёт 404** — для загрузок `curl -4`, у Gradle
  `systemProp.java.net.preferIPv4Stack=true` уже в `~/.gradle/gradle.properties`. Android SDK (для `app/`)
  — `~/.local/opt/android-sdk`; для `:core`/`:desktop` не нужен. Экрана нет — UI тут не посмотреть
  (unit/интеграция — да).
- **Windows 10**: где и как КК будет запускать/смотреть приложение — **открытый вопрос к Elyor** (§13):
  варианты — Windows-ПК/ВМ Elyor с OpenSSH-сервером и обратным туннелем сюда (по аналогии с
  `~/.local/bin/phone-adb` для телефонов), либо GitHub Actions + ручная проверка Elyor.
- Без проверки на Windows — **не коммитить фичу как готовую** (см. `CLAUDE.md`).

## 11. Правила работы (кратко; полностью — `CLAUDE.md`)

Цикл: код → сборка → запуск/проверка фактом → коммит (сам, без спроса) → пуш (бэкап). Публикация релиза —
только по явному слову Elyor. Коммиты по-русски с префиксами (`feat(…)`, `fix(…)`), по одному изменению,
автор PICO-SOFT, в теле — что проверено фактом и что нет. Память = журнал решений («почему» + «что отвергли»).
